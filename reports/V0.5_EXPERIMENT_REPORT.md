# V0.5 Experiment Report
## Repeated Network Security Regression and Evidence Validation

**Project:** Zero Trust Network Security Lab
**Version:** V0.5
**Experiment date:** 2026-10-22 (UTC)
**Result:** PASS — 3/3 rounds, 18/18 scenario executions

## 1. Objective

Evaluate the repeatability of the existing V0.4 network
microsegmentation tests and produce verifiable evidence in
raw-text, JSON, and CSV formats.

This version extends testing and evidence management.
It does not introduce a new access-control architecture.

## 2. Laboratory Environment

- Platform: Windows 11 with WSL2 Ubuntu 24.04.
- Four Linux namespaces: employee-ns, app-ns, data-ns,
  and zt-gw-ns.
- Three isolated veth links connected to zt-gw-ns.
- Internal subnets: 10.200.10.0/30, 10.200.20.0/30,
  and 10.200.30.0/30.
- Firewall: nftables, table `inet ztlab_v04`.
- No external network access or NAT was configured
  as part of the laboratory topology.

## 3. Access-Control Policy

The gateway forwarding chain uses a default-drop policy.

Explicitly allowed new connections:

1. Employee (10.200.10.2) to Application
   (10.200.20.2), TCP port 8080.
2. Application (10.200.20.2) to Data
   (10.200.30.2), TCP port 5432.

Established and related response traffic is permitted.
Other forwarded traffic is denied.

The test service on TCP port 5432 is a temporary
Python-based test endpoint, not a PostgreSQL database.

## 4. Test Method

The existing root-owned V0.4 test runner was invoked
through the V0.5 orchestration program.

- Requested rounds: 3
- Expected scenarios per round: 6
- Total scenario executions: 18
- Each run was bounded by a process timeout.
- Testing stopped on a failed round.
- Individual logs, JSON summary, and CSV scenario
  records were preserved.

- `round_01.txt`, `round_02.txt`, `round_03.txt`

These checks detect inconsistencies against the stored

## 8. WSL Restart and Recovery Observation

Before the experiment, the previous WSL network namespaces
were found missing while the deployment state file still
reported PHASE=ACTIVE.

The previous state file was safely archived:

`/var/lib/ztlab-v03/state.stale-20261022T090857Z`

After re-deployment:

- The V0.3 topology validator reported zero failures.
- The V0.4 nftables policy loaded successfully.
- The active forwarding rules were inspected before testing.

Automatic recovery from this stale-state condition
has not yet been implemented or validated.

## 9. Limitations

- This is a controlled namespace-based prototype.
- It does not implement a complete Zero Trust system.
- No real user identity verification or continuous
  authorization is demonstrated.
- The tests cover six predefined traffic scenarios.
- Fault injection, concurrent load, and production
  deployment behavior remain untested.
- Evidence consistency does not establish resistance
  to deliberate modification of all stored evidence.

## 10. Conclusion

V0.5 successfully repeated the V0.4 firewall regression
suite for three rounds. Every round passed all six
defined scenarios, and the saved evidence passed
independent format and hash-consistency checks.

The results support repeatability within the tested
laboratory conditions. They do not establish
production-grade Zero Trust security.
